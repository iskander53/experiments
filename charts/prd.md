# Дашборд отклонений склада

## Архитектура

Snowflake → in-memory кэш (Node.js) → REST API (Express) → React + Plotly.js.

Один тяжёлый SQL выполняется при старте, результат живёт в памяти. Все запросы фронтенда — фильтрация и агрегация по кэшу, без повторных обращений к Snowflake.

## Структура данных

**Метрики** (агрегируются через SUM):
- `deviation_count` — количество отклонений
- `quantity` — штуки товара
- `amount_rub` — сумма в рублях

**Измерения** (группировка и фильтрация):

| Измерение | Описание | Где используется |
|-----------|----------|-----------------|
| `blame` | Виновник: Склад / Поставщик / Получатель | Определяет вкладку. «Отклонения склада» = жёстко Склад. «Отклонения» = доступен как измерение |
| `deviation_category` | По количеству / По качеству / По времени | Фильтр-чипсы в сайдбаре |
| `deviation` | Группированное отклонение (недостача, повреждение, излишек, ...) | Пивот, treemap |
| `deviation_source` | Сырое отклонение из источника | Только в модалке правого клика (drill-down) |
| `stage` | Этап (Приемка, Упаковка, Отгрузка ГМ, ...) | Группировка |
| `warehouse` | Склад (BD1, KDZ, DWC, ...) | Глобальный фильтр в шапке |
| `customer` | Заказчик | Группировка |
| `item_type` | Тип товара (BIG/SMALL/NORMAL/BOX/STOCK) | Группировка |
| `employee` | Сотрудник | Только в детализации |
| Время: `hour`, `shift`, `day`, `week`, `month` | Временные разрезы | Столбцы пивота, ось гистограммы |

**Два уровня отклонений**: SQL группирует сырые причины (`deviation_source`, напр. «Механические повреждения») в обобщённые (`deviation`, напр. «повреждение»). Визуализации работают с `deviation`, правый клик показывает `deviation_source`.

## Источник данных

Один SQL-запрос (~1000 строк CTE) объединяет три источника через UNION ALL:

- **BD** — рекламации (`msk_expedition_claim`), потери/излишки (`MSK_LOGS_OF_WH_OPERATIONS`), простои 30+ дней, опоздания ГМ
- **KDZ** — потери на LOST/888888, рекламации, простои 30+ дней, дефекты поставщика (reject_data + defect_flags)
- **DWC** — повреждения/недостачи при приёмке, простои 30+ дней, дефекты поставщика

Каждый источник приводится к единой схеме из 18 колонок. Дата — единственный параметр запроса.

## Кэширование

- При старте сервера загружаются все строки за запрошенный диапазон дат в массив `DefectRow[]`
- Все API-запросы (`/api/data`, `/api/pivot`, `/api/data/rows`) — `Array.filter()` + `Map`-агрегация по кэшу
- При расширении диапазона дат дозагружается только недостающий кусок, дедупликация по ключу строки
- Значения измерений (`/api/dimensions`) — захардкожены, без запросов к Snowflake

## Фронтенд

**Вкладки**: «Отклонения» (все, blame как измерение) и «Отклонения склада» (blame=Склад, скрыт).

**Компоненты**:
1. **Гистограмма** — столбцы (кол-во) + линия (₽) по времени, ось синхронизирована с пивотом
2. **Пивот-таблица** — строки (измерения) × столбцы (время), выбор метрик через чипсы
3. **Treemap** — иерархия до 4 измерений, выбор меры

**Взаимодействие**:
- Клик по ячейке пивота → фильтрует treemap
- Правый клик (пивот или treemap) → модалка с сырыми строками и `deviation_source`
- Глобальные фильтры (дата, склад) в шапке, применяются кнопкой
